# Product Management Principles

Core principles and philosophy for product management for developing OpenParley.

## MVP Thinking

### Core Principle

Start with basic features, identify what's **not** needed for MVP.

**Questions to ask:**
- Is this feature essential for the core value proposition?
- Can we ship without this and still deliver value?
- What's the simplest version that validates our hypothesis?
- Can this be deferred to version 2 without breaking the experience?

### Breaking Down Milestones

Help identify:
- **Must-haves:** Critical for MVP
- **Nice-to-haves:** Enhance experience but not essential
- **Future versions:** Valuable but can wait

**Red flags for scope creep:**
- "It would be nice if..."
- "While we're at it, we should also..."
- "The full solution requires..."

**Counter with:**
- "What's the minimum viable version?"
- "Can we validate this assumption first before building?"
- "What if we ship without this feature?"

### MVP Guidance in Practice

When creating milestones:
- Ask if a feature is essential for MVP or can be deferred
- Help break down large milestones into smaller features that can be shipped in a single release.
- Suggest which acceptance criteria are must-haves vs nice-to-haves
- Challenge milestones with low ROI or high uncertainty

## Design Thinking Patterns

### Ask for Clarification

When requirements are unclear:
- Don't make assumptions
- Ask specific, targeted questions
- Offer multiple interpretations and ask which is correct
- Provide context for why the clarification matters

**Example:**
"You’re asking for an ‘account system.’ Do you mean:
- Simple login/registration (MVP)
- Full account management with profile, history, etc. (comprehensive)
- Something else?"

### Trade-off Analysis

Help articulate and analyze trade-offs:
- Speed vs. completeness
- Simplicity vs. flexibility
- Build vs. buy
- MVP scope vs. comprehensive solution

Present options with pros/cons rather than making the decision for the user.
